## Found while validating

1. **Login cookies authenticate silently.** DummyJSON sets `accessToken` and `refreshToken` cookies at login, and Newman keeps a cookie jar like a browser. The first run's "no token" requests therefore got `200` instead of `401`. Fixed with `protocolProfileBehavior.disableCookies: true` at collection level, so every request is authenticated only by the headers it declares.
2. **JUnit output omits script errors.** A JavaScript syntax error in a test script shows in Newman's CLI summary and exit code, but not in `junit.xml`. Pass/fail must come from the exit code, never from counting JUnit failures alone.
3. **`CryptoJS` is a sandbox global.** `const CryptoJS = require('crypto-js')` is a redeclaration error; the collection uses `cryptoJs`.
4. **First-connection failures (`AggregateError`), root-caused and fixed.** It happened twice, both times on a run's first request, and every token-dependent request after it failed too. Cause: `dummyjson.com` resolves to IPv6 and IPv4 addresses, and Node 20 (which runs Newman) gives each connection attempt only 250 ms (`net.getDefaultAutoSelectFamilyAttemptTimeout()`), so a slow first connection fails on every address. Fix: `scripts/run-newman.sh` sets `NODE_OPTIONS=--network-family-autoselection-attempt-timeout=2000`. After the fix, 5 consecutive main runs passed (201 of 201 assertions each).
6. **No account details in failure messages.** Username checks assert a true/false match instead of `eql`, so a failure can't print the test user's name into a report.
5. **Search terms checked live:** `perfume` returns 0 products, so it was not used; the CSV's 5 matching terms and 1 non-matching term all behave as expected.
